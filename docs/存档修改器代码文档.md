# GBFR 自用修改器 — 代码文档

## 1. 项目用途与架构概述

本项目是一个基于 Python 的《碧蓝幻想：Relink》(GBFR) **本地存档修改工具**，无需打开游戏即可直接修改 `SaveData1.dat`。当前版本为 v1.4（GUI 标题 `GBFR 存档修改器 v1.4`）。核心特性：

- 每次写入前**自动备份原档**（生成 `SaveData1.dat.<操作名>_<时间戳>`），并**重算存档校验和**；
- 所有写操作支持 `--dry-run` / GUI「预览(不写入)」，先确认再落盘；
- v1.1 起所有涉及角色的命令/界面都支持直接用**游戏内角色名**（中英双语，取自游戏本体文本表），兼容原 `PLxxxx` 代码与 `0x` 哈希；
- **v1.3 召唤石自定义**：DLC 2.0 召唤石背包（id_type 1451-1460）完整编辑 —— 种类/主加护/副词条/等级/阶级/4 槽装备，全部**真实名称**显示（哈希已逆向，目录见 `catalog_summon.json`）。

整体分三层：

```
gbfr_gui.py / gbfr_cheat_tool.py   ← 应用层：GUI(tkinter) + CLI(命令行)，共用同一套修改逻辑
        │  GUI: import gbfr_cheat_tool as gct（复用其常量与函数）
        ▼
catalog*.json / gem_*.json / chara_names.json …  ← 数据层：从游戏 data.i 提取的目录/合法性表
        ▼
gbfr-save-editor/gbfr_editor/core/{gbfr_save.py, hashing.py}  ← 核心层（vendored）：
     FlatBuffers 存档解析 + XXHash64 校验和重算 + GBFR 自定义 XXHash32
```

- **核心层**来自开源项目 `xcier/GBFR-Save-Editor`，已 vendor 到
  `save_tool/gbfr-save-editor/GBFR-Save-Editor-main/gbfr_editor/core/`：
  - `gbfr_save.py`（约 757 行）：存档的打开、按 id_type 索引记录、读写字段；
    校验和用 XXHash64，种子固定为 `0x2F1A43EBCD`，并按 `HASH_SECTION_INFOS`
    （11 组 (偏移,长度) 段表）对存档各段重算哈希。
  - `hashing.py`（67 行）：GBFR 自定义 XXHash32 变体（种子 `0x178A54A4`，
    注释注明移植自 GBFRDataTools.Hashing.XXHash32Custom），用于字符串 ID/哈希匹配。
- **CLI 层** `gbfr_cheat_tool.py`（约 53KB，最大的源码文件）承载全部修改逻辑：目录加载、名称解析、物品/因子/角色/召唤石/配装/武器祝福/上限突破/小钳蟹的读写函数与备份校验。GUI 只是它的"壳"，直接 `import gbfr_cheat_tool as gct` 调用其中的常量（`ID_*`、`CAT`、`GEMCAT`、`CHARSCAT`…）和函数（`save_and_backup`、`add_sigil_to_save`、`check_equip_limit`、`legal_secondary_ids`、`get_overmastery` 等）。
- **数据层**是一组 JSON 目录（见 §2），由 `build_catalogs.py` / `extract_tables.py` 从游戏本体 `data.i` 归档提取生成。

## 3. gbfr_gui.py：功能与实现要点

文件头注释：「GBFR 存档修改器 - 图形界面(GUI)入口；基于 gbfr_cheat_tool.py 的本地存档修改功能，
提供 tkinter 界面」。启动方式 `python gbfr_gui.py`（或打包后的 exe）。源码共 890 行。

### 整体结构

- **顶部栏** `_build_top()`：
  - 存档路径输入框（默认值 `gct.DEFAULT_SAVE`）；
  - 「浏览…」用 `filedialog.askopenfilename` 选择 `.dat`，选完自动强制重开并刷新；
  - 「打开并刷新」手动重新读盘（外部改动/存档被替换场景）;
  - 「备份当前存档」：shutil.copy2 复制为 `<路径>.manual_<时间戳>`；
  - 右侧「强制写入(游戏运行中,有风险)」复选框，值传给各写操作的 `force=` 参数。
- **选项卡** `_build_notebook()`：共 8 个页签 —— 物品 / 因子 / 角色 / 召唤石 /
  配装方案 / 上限突破 / 小钳蟹 / 祝福；每个页签下方有深色只读输出框 `_mk_out()`（bg `#101418`）。
- **日志**：底部全局日志框 + `LogCapture(io.StringIO)` 类，把 `print` 重定向进 GUI 日志
  （write 时临时解锁 Text、插入、滚动到底再锁回），使 CLI 代码的原生 print 直接显示在界面里。
- **角色下拉框** `_chara_cb()` / `_chara_choices()`：选项为「中文名 (PLxxxx)」形式，排除 dummy 槽
  `PL000B`（注释：非真实角色/LookDev）；Combobox 为 `state="normal"`，允许手动输入名字/PL 代码/0x 哈希；
  默认选中第一个有名字的角色（PL0000 古兰）。

### 性能缓存（重要实现要点）

- `_open()`：路径不变时**复用已打开的 `gct.GBFRSaveData` 对象**——源码注释注明重开存档约需 2.3s；
- `_vm(idt)`：对每个 id_type 的记录字典(vm)做缓存，同一存档打开期间记录结构不变可直接复用；
- 写档成功后调 `_invalidate()`（只清 vm 缓存、save 对象继续复用）;手动刷新走 `_force_reopen()` 完全重读盘。

### 各页签实现要点

所有写操作统一走 `gct.save_and_backup(save, path, op_name, force=…)`
（自动备份 + 校验和重算），成功后 `_invalidate()` 并提示备份文件名：

- **物品**：列表 = `ID_ITEM_ID`(1801) × `ID_ITEM_COUNT`(1802) 两个 vm 关联，支持中/英/0x 哈希搜索；
  改数量时按物品哈希在 1801 里定位槽位（物品必须已存在于存档，否则报错），再对 1802 做 `find_first/set_first_value`。
- **因子**：列表来自 `GEMCAT['sigil_info']`，副词条标记 `+`；「生成合法因子」流程 =
  名称解析(`find_sigil`) → 等级截断到主词条 `max_level`（不填默认满级）→
  `_resolve_secondary()` 校验副词条（固定副词条 / `legal_secondary_ids` 合法性池 + `_can_mix` 合成规则，非法即拒绝并给出中文错误）→
  若指定装备角色先 `check_equip_limit()`（12/13 格上限防闪退保护）→ `add_sigil_to_save(..., dry=)`；
  提供"生成(写入存档)"与"预览(不写入)"两个按钮。
  注意：少数 V+ 因子（如 万能药＋/霸体＋/自动药水＋）在 gem.tbl 的 `SkillId1` 是无功能占位技能，
  生成时会经 `sigil_primary_hash()` 修正为同名无+版的真实主词条，避免写入错误因子。
- **角色**：按 2703(因子哈希) + 2706(归属角色哈希) 关联统计各角色已装备因子数（跳过 EMPTY）;
  查看单角色因子时读 2704(等级) 及 `TRAIT_REC_BASE + idx*100` 的词条记录（idx = 槽位 − GEM_SLOT_BASE）;
  「卸下指定」按槽号把该角色的 2706 置 EMPTY，并调 `sigil_equip_unregister()` **从角色 1403 装备列表注销因子序列号**；
  「卸下全部」则遍历该角色所有因子执行同样操作。
  （源码/README：只写 2706 游戏装备界面不显示，必须同步登记/注销 1403）。
- **召唤石（v1.3，DLC 2.0 背包系统）**：读/写 id_type **1451-1460**（1451=4 槽装备 SlotID、
  1452/1453=登记目录+标志、1454=最大 SlotID、1455=解锁、1456=SlotID、1457=种类哈希、
  1458=[主加护,副词条]哈希、1459=[主级,副档]、1460=阶级）。
  所有哈希经 `catalog_summon.json`（逆向自 GBFR PE Patch Tool 数据）反查为**真实名称**;
  支持列表(★=已装备)/详情/编辑(种类/主加护/副词条/等级/阶级)/新增(自动登记 1452、SlotID=max+1)/
  换种类(重建 SlotID 并迁移 1451 装备引用)/4 槽装备;等级上限按目录 maxLevel(主加护再被 15 钳制),
  组合不在该种类 2.0.2 天然词池时警告不拒绝。旧版 3101-3115 记录含义未确认,保留 `summons legacy list` 只读展示。
- **配装方案**：以 JSON 存于 `gct.WRITE_DIR`（结构 `{chara, sigils:[{slot,gem,level}]}`）;
  恢复时先注销当前全部装备，再逐槽重写 2706、把 2707 标志规范化为低 2 位 = 2 的装备行格式，并 `sigil_equip_register()` 重新登记。
- **上限突破**：`OM_EFFECTS` 效果下拉 + 槽位 0–3 + 数值 0–1023；读/写走 `get_overmastery` / `set_overmastery`（传空效果名+0 = 清槽，另有"全部清空"循环 4 槽）;输出展示「显示值(含星级)」与「存档值/1023」（512=满档/10⭐，1023=改档上限）。
- **小钳蟹**：硬编码物品哈希改数量——普通小钳蟹 `0xEE2559C6`、漆黑小钳蟹 `0x9FBA96D1`;
  勾选后漆黑蟹像(`0x076A9F41`)置 1，并调 `complete_crab_quests()` 完成收集任务标志（物品需先在存档中存在，否则只警告不写）。
- **祝福(武器祝福)**：类型下拉来自 `gct.WRIGHT_TYPES`（恐惧/活力/强化/封印）;3 行「词条+等级」
  （默认 20/15/10，上限 `WRIGHT_MAX_LEVEL`=20），"刷新词条列表"从**当前存档**调 `wrightstone_trait_pool()`
  拉取实测合法的 71 种词条填充下拉框（保留已选值）;`add_wrightstone(save, wt[2], traits, dry=)` 写入 ItemManager **50000+ 槽位**，序列号 = 当前最大 +1；不填词条时写该祝福类型的默认词条。

### main()

`tk.Tk()` → `App(root)`（构造异常则销毁窗口并抛出）→ `root.mainloop()`；
启动后 50ms 延迟触发一次 `refresh_all()` 打开默认存档。

## 4. README.md 使用说明摘要

- **环境**：Python 3.10+，需 `msgpack`（`pip install msgpack`）;修改前须**完全退出游戏（含 Steam 云同步）**避免存档被覆盖。
- **CLI 用法**：`python gbfr_cheat_tool.py [--save 存档路径] <命令>`，命令包括：
  - `items list [关键词]` / `items set <物品> <数量>`；
  - `sigils list/add <因子> [--level N] [--secondary 词条] [--equip PLxxxx] [--dry-run]`;
  - `chars list/sigils/equip/unequip/clear`;
  - `summons list [关键词] [--all]` / `summons show <槽号>` / `summons set <槽号> [--type --main --sub --main-level --sub-level --rank]` / `summons add <种类> [...] [--equip 1-4] [--dry-run]` / `summons equip|unequip <1-4>` / `summons catalog|traits|subparams [关键词]` / `summons legacy list`;
  - `loadout list/save <名> <PLxxxx>/restore <名>`;
  - `wrightstone list/traits/add --traits "词条:等级,..."`;
  - `overmastery list/set/clear <PLxxxx>`;`crab --wee N --dark N --statue [--count]`。
- **角色名支持（v1.1+）**：中文名精确/包含匹配、英文名不区分大小写、GUI 下拉值「欧根 (PL0500)」、PL 代码、0x 哈希均可用；列表输出统一 `欧根 (Eugen) [PL0500]`;部分预留槽（PL2000、PL3000~PL3900）文本中无名，仍显示代码。
- **合法性**：`sigils add` 生成游戏真实存在的因子；副词条严格校验三个来源池——①固定副词条(自带 SkillId2)；②掉落/抽卡池(`gem.SkillTypeLotIdForRandom2ndSkill→skill_type_lot→skill_lot`)；③V+ 合成池（183 技能，游戏合成 = 两个 V+ 因子四技能随机混取前 2）;无 "+" 版因子在合成界面灰色不可选。
- **防闪退**：每角色默认最多 12 个因子，第 13 格需天赋盘「因子栏位解锁」(效果 0x7B727910) 点亮；超上限拒绝写入并提示。
- **备份**：每次写入生成 `SaveData1.dat.<操作名>_<时间戳>`，回退时把备份改名覆盖即可。

## 5. PyInstaller 打包信息（GBFR存档修改器.spec）

- **入口脚本**：`gbfr_gui.py`；输出 exe 名为 **`GBFR存档修改器`**。
- **窗口程序**：`console=False`（无控制台）、`upx=True`、`debug=False`、单文件 EXE。
- **datas（随包数据）**：8 个 JSON 目录打包到根目录 `.` ——
  `catalog.json`、`catalog_chars.json`、`catalog_gem.json`、`catalog_sigils_full.json`、
  `catalog_summon.json`、`chara_names.json`、`gem_legality.json`、`gem_mix_pool.json`;
  另把 vendored 核心目录 `'gbfr-save-editor/GBFR-Save-Editor-main/gbfr_editor/core'`（相对 save_tool）原样打入。
- **hiddenimports**：`['gbfr_cheat_tool', 'gbfr_save', 'hashing']` —— GUI 通过运行时 `sys.path.insert(0, …)`
  动态导入这些模块（gbfr_save/hashing 来自 vendored 子目录），PyInstaller 静态分析不到，必须显式声明。
- **使用方式**：在 `save_tool/` 目录下执行 `pyinstaller GBFR存档修改器.spec`（spec 中 datas 为相对路径，须在 save_tool 内运行）;打包产物即 GUI exe，双击即可用，无需 Python 环境。

## 6. 数据来源说明（README 原文归纳）

- 存档解析/校验和：基于开源项目 `xcier/GBFR-Save-Editor`（FlatBuffers + xxHash64），已 vendor 至本目录；
- 物品/因子/词条目录：从游戏本体 `data.i` 归档提取（gem.tbl / skill.tbl / skill_status.tbl / 文本 .msg）;
- 哈希算法：GBFR 自定义 XXHash32（与游戏一致，见 vendored `hashing.py`）;
- 合成机制：参考 Nenkai relink-modding wiki（gem_mix 文档）与 1.3 官方更新说明。
